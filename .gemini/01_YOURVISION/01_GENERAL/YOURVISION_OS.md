# YOURVISION OS

Единый источник истины канала YourVision. Читать в начале каждой YV-сессии. Конфликт с любым другим документом разрешается в пользу OS.

**Последнее обновление:** 2026-05-17 (handover Gemini → Claude, post-ESC 2026)
**Автор канала:** только Claude. Gemini-инфраструктура архивирована в `07_ARCHIVE/`.

## 1. МИССИЯ И ПОЗИЦИЯ

Ультимативная русскоязычная экспертиза Евровидения и смежных музыкальных индустрий. Не фан-канал, не агрегатор новостей, не блог. Аналитический бюллетень - точность данных Bloomberg в эстетике Dazed.

Читатель приходит за тем, чего нет в других русскоязычных ESC-источниках:
- разбор стратегий вещателей и диаспор, а не пересказ пресс-релизов;
- цифры, котировки, движения - до того, как их подхватят другие;
- жёсткая оценка без смягчений и без восторгов.

## 2. ВОЙСБРЕНД: SNIPER (Bloomberg × Dazed, заточенный)

**Принцип:** один факт = одно предложение. Без воды, без эмоций, без хеджей.

### Что делаем

- Лид - всегда твёрдый факт или жёсткий вывод. Первое предложение содержит цифру или конкретное действие.
- Каждый абзац - один смысловой блок. Длинные периоды режем на короткие.
- Цифры абсолютные и относительные рядом: "436 баллов. +41 над вторым местом."
- Аналитика идёт после фактов, не до. Маркируем явно: "Что это меняет:".
- "Мы" использовать только в редакционных ремарках, не в нарративе. Авторская позиция - через выбор фактов, не через прилагательные.

### Что НЕ делаем

- **Слова-табу:** невероятный, потрясающий, ошеломительный, легендарный, уникальный, эпический, грандиозный, долгожданный, культовый, феноменальный, мощный, яркий, настоящий.
- **Хедж-обороты табу:** "стоит отметить", "интересно, что", "нельзя не сказать", "как известно", "по сути", "в принципе".
- **Запрет на риторические вопросы** в теле поста. Вопрос разрешён только в hook'е для опроса.
- **Запрет на эмодзи в теле текста.** Разрешены: флаги стран везде; одна иконка рубрики в h1; в метаданных и хэштегах свободно.
- **Запрет на восклицательные знаки** кроме прямой цитаты артиста/официального источника.

### Образец лида (Sniper)

> [Страна] выиграла ESC 2026. 436 баллов.
> Преимущество над вторым местом: 41 балл.
> Девиз сезона закрыт. Vienna 2027 отменена.
> ORF передаёт оргкомитет [вещателю].
>
> **Что это меняет:**
> - Big Five в 2027 пересматривают бюджеты.
> - Букмекеры закрыли все winner-линии в 02:14.
> - Диаспора [Страны] дала 12 из 18 max-баллов.

### Образец лида (так делать НЕЛЬЗЯ)

> Невероятная ночь в Вене подарила нам потрясающую победу!
> [Страна] - наш чемпион! Стоит отметить, что артист проделал
> долгий путь, и сегодня этот путь завершился триумфом...

## 3. ПУНКТУАЦИЯ И ТИПОГРАФИКА

- **Только дефис (-).** Никогда длинное тире (—), никогда среднее (–).
- **Кавычки:** «ёлочки» для русского, "прямые" для англоязычных названий песен.
- **Числа:** разделитель тысяч - неразрывный пробел или без разделителя. Никогда точка/запятая.
- **Время:** только Europe/Riga (EET/EEST). Никогда CET. Формат HH:MM, 24-часовой.
- **Даты:** DD.MM.YYYY в теле текста, YYYY-MM-DD в метаданных и именах файлов опционально.
- **Хэштеги:** в подзаголовках h2/h3 ЗАПРЕЩЕНЫ. Только в финальной строке поста.

## 5. ИНДЕКС ВЕНЫ (единая система оценки)

Каждый артист/выступление получает пять оценок 0-10. Индекс Вены = среднее × 2 = 0-100.

| Критерий | Что оценивается |
|---|---|
| Вокал | Чистота, диапазон, контроль, эмоциональная передача |
| Постановка | Сценография, хореография, свет, управление пространством |
| Novelty | Оригинальность, запоминаемость, неожиданность решений |
| Televote | Массовое соединение, хуки, момент, доступность |
| Jury | Артистизм, сложность, профессиональная подача |

**Грейды поста (Grade A/B/C/D - применяется к тексту, не к артисту):**

| Grade | Индекс | Действие |
|---|---|---|
| A | 80-100 | Публикуется без правок |
| B | 60-79 | Минорная правка |
| C | 40-59 | Переработка секций |
| D | <40 | Перезапись |

Старая система Grade Q/S/F/B/C/A по количеству знаков - отменена. Объём контролируется через колонку "Объём" в каталоге рубрик.

## 6. ФАЙЛОВАЯ СТРУКТУРА И NAMING

```
01_YOURVISION/
├── 01_GENERAL/             ← OS и инструкции (этот файл)
├── 02_KNOWLEDGE/           ← живой лор и базы (CHANNEL_LORE, MASTER_DATABASE, Live_Calendars)
├── 03_TEMPLATES/           ← живые шаблоны постов
├── 04_CONTENT/YYYY/MM/DD/  ← все опубликованные посты
├── 05_ASSETS/              ← медиа, звуки, документы
├── 06_TIMELINE/            ← master_plans и database (yv_season_2026.json)
├── 07_ARCHIVE/             ← всё, что больше не нужно (Gemini engine, старые планы, legacy bibles)
└── 08_HUB/                 ← YV Hub (index.html + data.js + assets) - editorial dashboard, deploy на GitHub Pages
```

**Имя файла поста:**

```
YV-DD.MM-HH-MM-[RUBRIC|COUNTRY]-Topic.md
```

Примеры (из реальных постов):
- `YV-16.05-22-00-LIVE-GRAND-FINAL.md`
- `YV-17.05-02-30-EU-GrandFinalDeepDive.md`
- `YV-12.05-15-00-FI-UMK27Announce.md`

Дефисы между HH-MM (не двоеточие). COUNTRY - ISO-2 (EU для общеевропейских). Topic - PascalCase без пробелов.

## 7. СТРУКТУРА ПОСТА

### Header (обязательный)

```
// ИД-ПОСТА: YV-DD.MM-HH-MM-RUBRIC-Topic
// ТЕМА: [одно предложение, что внутри]
// ДАТА ПУБЛИКАЦИИ: DD.MM.YYYY, HH:MM (Europe/Riga)
// ПРОТОКОЛЫ: YourVision, [RUBRIC]
// СТАТУС: ГОТОВ
```

`(EDITORIAL ANALYST V4.0)` и подобные - не пишем. Это legacy.

### Тело

1. **H1:** `[ФЛАГ СТРАНЫ] **[СТРАНА/ТЕМА: КЛЮЧЕВАЯ ХАРАКТЕРИСТИКА]**`
   - Начинается с флага страны (для общеевропейского - 🇪🇺, для регионального - 🌏).
   - Без иконки рубрики (никаких 🏛 🧬 🎯 📊 в видимом h1).
   - Без названия рубрики в видимом тексте (никаких «GLOBAL:», «DNA:», «VERDICT:»).
   - Рубрика остаётся только в `// ПРОТОКОЛЫ:` метаданных и в футере для аналитики.
   - Примеры:
     - `🇮🇹 **ИТАЛИЯ: Sal Da Vinci - голос неаполитанской традиции**`
     - `🇧🇬 **БОЛГАРИЯ: СОФИЯ / ПЛОВДИВ / ВАРНА - ТРИ ГОРОДА В ШОРТ-ЛИСТЕ ESC 2027**`
     - `🇪🇺 **ESC: EBU открыл регистрацию участников 2027**`
2. **Лид:** 1-2 предложения. Sniper-стиль. Цифра или твёрдый факт. Можно начать с `⚡️ BREAKING:` для T+0 экстренных публикаций.
3. **Подзаголовки внутри тела:** ТОЛЬКО `**жирный текст**`. НИКОГДА `##` или `###`. Markdown-h2/h3 в Telegram рендерятся плохо или не рендерятся вовсе. Только `**Что известно**`, `**Что это меняет**`, `**Контекст**` и т.п. - инлайн bold.
4. **Контент** по структуре рубрики (см. §4 - конкретные шаблоны в `03_TEMPLATES/`).
5. **Хук** в конце - для рубрик с опросом или дискуссией. Один конкретный вопрос с явным выбором, не риторика. Можно закрывать `💬` для приглашения к обсуждению.

### Footer (обязательный)

```
---
`Время чтения: X мин | [флаг] YourVision: [Рубрика]`

**Grade:** [A/B/C/D]
**Prompt:** [Midjourney-промпт, см. §8]
```

## 8. ВИЗУАЛЬНЫЙ СТАНДАРТ (Midjourney)

**Константа:** `--ar 1:1`. Никакого 16:9, никакого 9:16. Исключения - только по явному запросу оператора.

**Подпись на изображении:** только название рубрики (или темы) и `YourVision` + `levdanskiy` в нижнем углу. Никаких других надписей.

**Хвост промпта (обязательный):**
```
shot on 35mm film Kodak Portra 800, heavy film grain, Dazed magazine aesthetic --ar 1:1 --v 6.1 --style raw --s 750
```

**Шаблон промпта по рубрике:**

- **DNA / VERDICT:** одна фигура артиста, портрет, editorial pose, тёмный фон с одной точкой света;
- **RESET:** split-screen (2025 / 2026), две параллельные сцены;
- **ODDS:** аналитический фон - график, котировки, минимальная типографика;
- **GLOBAL / BREAKING:** документальный кадр с места события, без постановки;
- **SF / VISION:** широкая сцена, архитектура арены, толпа в глубине;
- **LIVE:** массивная 3D-надпись темы (например `GRAND FINAL`), сценический свет.

## 9. РАБОЧИЙ ЦИКЛ СОЗДАНИЯ ПОСТА

Аудит → look-ahead → план → текст → валидация → файл → синк лога.

### 9.1 Аудит перед написанием

Всегда в начале YV-сессии:
1. Прочитать этот OS (если давно не читал в текущей сессии).
2. Прочитать `02_KNOWLEDGE/YV_Season_2026.md` (state сезона 2026) и `YV_Season_2027.md` если уже создан.
3. Прочитать последнее в `04_CONTENT/2026/MM/DD/` - что уже опубликовано сегодня и вчера.
4. Прочитать `02_KNOWLEDGE/Live_Calendars/YV_ESC_Live_Calendar.md` - что в очереди.
5. Прочитать `06_TIMELINE/database/yv_season_2026.json` - источник правды по слотам.

### 9.2 Look-ahead 7d

Просмотреть в Live Calendar окно ближайших 7 дней. Любой PENDING с датой в [сегодня; +7] - обязательная тема для обсуждения с оператором в начале сессии:
- сегодня → готовим прямо сейчас;
- завтра → определяем угол и закладываем черновик;
- +2-7 → проверяем источники, готовимся.

Если PENDING без даты (TBA), но событие приближается по контексту - запросить уточнение у оператора.

### 9.3 План

- Определить рубрику (§4). Если не подходит ни одна - не писать.
- Проверить, что тема не дублирует пост последних 7 дней (grep по `04_CONTENT/`).
- Подобрать минимум 2 источника. Один официальный (EBU, вещатель, артист) + один независимый.

### 9.4 Текст

- Лид в Sniper-стиле (§2).
- Никаких слов-табу (§2) и пунктуационного мусора (§3).
- Цифры с источниками. Если источника нет - цифры нет.

### 9.5 Валидация (перед сохранением файла)

Чек-лист (автоматизирован через `voice-lint.sh` + pre-commit hook):
- [ ] Header заполнен полностью, время Riga
- [ ] H1 содержит иконку рубрики
- [ ] Лид - один факт, не лозунг
- [ ] Нет слов-табу
- [ ] Только дефис (`-`), нет `—` и `–`
- [ ] Нет хэштегов в h2/h3
- [ ] Footer с грейдом и промптом
- [ ] Промпт заканчивается на стандартный хвост (§8)
- [ ] `--ar 1:1`

### 9.6 Файл

Сохранить в `04_CONTENT/YYYY/MM/DD/[имя].md`. Если папки даты ещё нет - создать.

### 9.7 Синк лога (обязательный)

После публикации поста СРАЗУ обновить:

1. **Live Calendar** (`02_KNOWLEDGE/Live_Calendars/YV_ESC_Live_Calendar.md`):
   - Статус соответствующей строки → `COVERED`
   - В колонке "Пост" - путь к файлу
   - Если новый событие открылось в посте - добавить новую строку
2. **Season DB** (`02_KNOWLEDGE/YV_Season_2026.md` или `YV_Season_2027.md`):
   - Если пост содержит данные (артист, песня, дата нацотбора, девиз, ведущий и т.п.) - обновить соответствующую запись.
3. **JSON DB** (`06_TIMELINE/database/yv_season_2026.json`):
   - Если событие сезонного масштаба - добавить/обновить запись там же.

## 9bis. ПРОТОКОЛ АВТО-ОБНОВЛЕНИЯ ДАННЫХ

Источники данных, которые автоматически попадают в `02_KNOWLEDGE/` и `06_TIMELINE/database/`:

### А. Оператор присылает информацию

Когда оператор в чате сообщает факт (артист подтверждён, дата объявлена, изменился регламент и т.п.):
1. **Сначала** обновить соответствующую базу (`YV_Season_2026.md` / `2027.md`, Live_Calendar, JSON DB).
2. **Потом** написать пост, если факт значимый.
3. **Не наоборот.** База - источник правды, пост - продукт.

### Б. Данные в готовых постах

При аудите (§9.1) сканировать недавние посты (`04_CONTENT/2026/MM/`) на содержимое:
- упоминания артистов/песен/дат, которых ещё нет в Season DB → добавить;
- упоминания событий, которых нет в Live Calendar → добавить со статусом COVERED;
- упоминания девиза/места/ведущих сезона → апдейтить state-файл.

### В. Внешние источники

EBU / вещатель / артист подтвердили факт - оператор пересылает ссылку:
- Прочитать (WebFetch если URL доступен).
- Обновить базу (А).
- Решить с оператором, нужен ли пост.

### Правило истинности

При конфликте источников: оператор > EBU > вещатель > артист > букмекер > Wiki > соцсети. Дата проставляется к каждой записи (когда подтверждено и кем).

Между концом ESC 2026 и стартом первых нацотборов 2027.

### 🌱 PRE-SEASON BUILD (01.09.2026 - 31.12.2026)

Анонсы вещателей о возвращении/неучастии, имена ведущих, форматы нацотборов.

- DNA-портреты ключевых артистов с подтверждённым участием.
- VISION ежемесячно: общая карта сезона 2027.

### 🔥 ACTIVE SEASON (01.01.2027 - 16.05.2027)

Полный цикл нацотборов, репетиций, конкурса. Темп - ежедневный.

- EBU / eurovision.tv для регламента и официальных списков.
- ORF (2026), [вещатель-хозяин] (2027).
- Национальные вещатели для нацотборов.
- Букмекеры для ODDS: указывать конкретного букмекера в каждом ODDS-посте.

**Что НЕ источник:**

- Wikipedia - не цитируем как первоисточник.
- Telegram-каналы конкурентов - не цитируем никогда.

### 11.1 Иерархия источников

При конфликте: **оператор > EBU > вещатель > артист > букмекер > Wiki > соцсети**.

Дата проставляется к каждой записи в `.md`-базах: когда подтверждено и кем.

### 11.2 Attribution в постах: правило двух блоков

Если новость содержит и **официальные факты** (вещатель/EBU явно заявили), и **оценки прошлых лет / инсайдерские дедлайны / параметры по шаблону прошлых сезонов** - разделять их в посте на два явных подзаголовка.

**Структура:**

```
**Что известно официально**
- [то, что вещатель/EBU явно опубликовал в этой новости]
- [только то, что прямо в источнике]

**Что повторяется по шаблону прошлых сезонов**
- [то, что инсайдерские источники / фан-агрегаторы указывают на основе прошлых лет]
- [возраст/гражданство/формат, если не подтверждены 2026 а взяты из 2024-2025]
- [конкретные даты-ориентиры, если в этом году вещатель сказал только «до конца месяца»]
```

Это правило родилось 19.05.2026 на MK-кейсе: MRT публично сказала «до конца мая», а фан-источники указали 29.05 - в первой редакции 29.05 пошло как факт MRT, что неточно. Теперь два блока с явной атрибуцией.

**Когда не применять:** если новость монолитная (один официальный источник, нет инфо «по шаблону»), достаточно одного блока «Что известно». Не размывать ради структуры.

**Что говорить если источник один и неофициальный:** не публиковать. Sniper-стандарт: «Если источника нет - цифры нет» (§9.4). По одному фан-источнику без официального бекапа пост не выходит.

### 11.3 Маркеры неопределённости в Calendar

В `Live_Calendars/YV_ESC_Live_Calendar.md` для дат-ориентиров использовать префикс `~`:
- `29.05` - точная дата из официального объявления
- `~29.05` - ориентир по прошлым сезонам / инсайдерам
- `TBA` - конкретной даты нет, окно объявлено («до конца мая»)
- В колонке «Событие» приписка `(ориентир по прошлым сезонам)` для `~`-дат.

### 13.1 Sync постов в Hub

Hub-секция «Latest news» (`data.js.news[]`) питается двумя кооперативными скриптами:

| Скрипт | Источник | Маркер `id` | Триггер |
|---|---|---|---|
| `08_HUB/tools/yv_tg_sync.py` | Telegram-каналы | `"70"` (или другой channel id) | Cron каждые 15 мин |
| `08_HUB/tools/sync_local_posts.py` | `04_CONTENT/YYYY/MM/DD/YV-*.md` | `"local"` | Вручную после написания поста |

**Кооперация:** cron сохраняет `id="local"` записи неприкосновенными, добавляет к ним свежие TG-посты, сортирует по `ts` desc, обрезает до 25.

**Workflow для нового поста:**
1. Написал .md → сохранил в `04_CONTENT/`.
2. `python3 08_HUB/tools/sync_local_posts.py` → пост в Hub.
3. Опубликовал в Telegram → следующий cron-тик добавит TG-версию рядом.

**Дедуп:** на MVP-уровне не реализован. Один и тот же пост может появиться дважды (как `local` и как `70`). Это допустимо, но можно после публикации в TG удалить локальный sync вручную (переименовать .md или повторно запустить `sync_local_posts.py` после удаления из 04_CONTENT).

Подробности: `08_HUB/tools/README.md`.

**Безопасность:** GitHub PAT в remote URL деплоя и Telegram-токен в архивных скриптах - известные проблемы. Не использовать архивные скрипты без ротации токенов. См. предупреждения в `08_HUB/README.md`.
