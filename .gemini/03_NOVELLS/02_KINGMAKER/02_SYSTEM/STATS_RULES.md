# 📊 KINGMAKER - STATS RULES v1.0

Правила движения чисел в KM. Источник истины - `STATS.json`. Этот документ - формулы.

См. также: [[NOVELLS_OS]] раздел 5, [[KM VOICE_LOCK]], [[KM_AFFINITY_UNLOCKS]], [[KM STATE.md]].

**Архитектура трёх слоёв** (вводятся фазно):
- **Phase 1** - Слой 1: Reputation + Affinity + **Protagonist Traits** (см. раздел 0)
- **Phase 2** - добавляется Слой 2: World State (regime stability + BV reach)
- **Phase 3** - добавляется Слой 3: Character Pressure (личные уязвимости 6 претендентов)

## 0. PROTAGONIST TRAITS - 4 оси личности Норы

**Принцип:** каждое решение читателей сдвигает Нору по одной или двум осям. К концу сезона - **узнаваемый профиль личности**, определяющий доступные финалы.

### Четыре оси

| Ось | Минус (-50) | Плюс (+50) |
|-----|-------------|------------|
| **calculation_vs_empathy** | Расчёт - решения через данные, цифры, результат | Эмпатия - решения через людей, эмоции, отношения |
| **shadow_vs_public** | Тень - ходы невидимы, действия через посредников | Публичность - ходы открытые, лицо видно |
| **ruthless_vs_merciful** | Жёсткость - готовность уничтожить ради цели | Милосердие - сохраняет тех, кто проиграл |
| **paranoid_vs_trusting** | Паранойя - каждый источник проверяется дважды | Доверие - принимает информацию по интуиции |

Старт каждой оси: **0** (нейтрально). Шкала: [-50, +50]. Не выходит за пределы.

### Формулы движения

**Daily poll:**
- 1-2 оси двигаются на ±5-10 каждая
- Деltas прописываются в `stats_deltas` опроса в POLL_LOG.json
- Синтаксис: `{"target": "protagonist", "axis": "calculation_vs_empathy", "delta": -8, "reason": "..."}`

**Major Choice (4 опции):**
- 2-3 оси двигаются на ±10-15

**Phase Final (6 опций):**
- 2-4 оси двигаются на ±15-25
- Крупный сдвиг траектории

### Типовые сценарии движения

| Выбор | Возможные deltas |
|-------|------------------|
| Сделать ход публично, на заседании | shadow_vs_public **+10** (к публичности) |
| Действовать через посредника | shadow_vs_public **-10** (к тени) |
| Уничтожить компрометирующего | ruthless_vs_merciful **-10** + calculation_vs_empathy **-5** |
| Дать второй шанс | ruthless_vs_merciful **+10** + paranoid_vs_trusting **+5** |
| Выбрать данные над намёками | calculation_vs_empathy **-8** |
| Принять чувства персонажа | calculation_vs_empathy **+10** |
| Проверить источник через Хлою | paranoid_vs_trusting **-5** |
| Принять слова на веру | paranoid_vs_trusting **+8** |

### Видимость для читателя

- **Daily** - **скрыто**. Читатель не видит чисел, только последствия в сценах.
- **Phase end** - **раскрывается** через **TRAJECTORY POST**:
  - Сводка движений за фазу
  - Нарративная интерпретация
  - Имя складывающегося архетипа (если уже определился)

### Архетипы (определяются по комбинациям к Phase 3)

| Архетип | Доминирующие оси | Концовка-маркер |
|---------|------------------|-----------------|
| **Архитектор** | Расчёт + Тень + Жёсткость | Строит структуру, не считая стоимости |
| **Освободитель** | Эмпатия + Публичность + Милосердие | Открыто борется за справедливость |
| **Сорока** | Тень + Паранойя + Жёсткость | Собирает компромат, не доверяет никому |
| **Тайный союзник** | Тень + Доверие + Эмпатия | Работает за кулисами для друзей |
| **Стратег** | Расчёт + Доверие + Милосердие | Тонкий баланс, строит альянсы |
| **Магистр** | Расчёт + Публичность + Милосердие | Формальная власть, справедливость |

К каждому архетипу привязана **одна доступная концовка** (см. ENDINGS.md). Финальные опросы (Phase 3 финал) учитывают архетип - концовки, не соответствующие архетипу, недоступны.

### Workflow

```
Опрос закрывается → stats_deltas включает trait deltas →
stats-apply.py применяет к protagonist.traits →
проверка не вышло ли за [-50, +50] →
запись в trait.history →
архетип не пересчитывается ежедневно (только в TRAJECTORY POST)
```

## 1. REPUTATION (котировка)

**Принцип:** публичное восприятие шансов претендента. Букмекерская логика.

**Шкала:** обычно 1.5-15.0.
- Низкое число (1.5-3.0) - явный фаворит.
- Среднее (3.0-6.0) - реальные шансы.
- Высокое (6.0-15.0+) - тёмная лошадка.

**Тренды:** ↑↑ / ↑ / → / ↓ / ↓↓ - где ↑ означает котировка УЛУЧШИЛАСЬ (число упало), ↓ - ухудшилась (число выросло). Знаки противоположны числовому движению, потому что показывают шансы артиста, не саму цифру.

### Стартовые значения (Phase 1 День 1)

| Персонаж | Старт | Логика |
|----------|-------|--------|
| Адриан | 2.5 | Кронпринц, очевидный наследник по праву рождения |
| Беатрис | 3.2 | Кровь короны, публичное лицо, недооценка |
| Леон | 4.5 | Outsider с медиа-империей, реальное влияние |
| Изабелла | 5.0 | Outsider, не родственница, но контролирует поток информации |
| Дэмиен | 6.0 | Не в линии преемствия, но держит ключи Канцелярии |
| Хлоя | 12.0 | Невозможный кандидат на бумаге - бастард без фамилии |

### Формулы движения

**Black Velvet слив, направленный на персонажа:**
- Лёгкий намёк: +0.3 до котировки (хуже шансы)
- Серьёзная утечка с конкретикой: +0.8 до +1.5
- Полный документ / доказательство: +1.5 до +3.0

**Удачный публичный ход персонажа:**
- Реактивная защита (опровержение): -0.2
- Контр-удар (свой слив против обидчика): -0.5
- Стратегическая инициатива: -0.8 до -1.5

**Скандал с участием персонажа (не Black Velvet):**
- Слух / журналистский вопрос: +0.3
- Подтверждённое поведение: +0.8
- Снятие маски: +1.5

**Поддержка от Норы (явная):**
- Нейтральная: 0
- Лёгкая: -0.2
- Открытая: -0.5

**Поддержка от Норы (тайная):**
- Сам персонаж не знает: 0 (но affinity двигается)

### Каскад
Когда у одного персонажа котировка падает (становится хуже), у конкурентов котировка слегка улучшается. Распределение:
- Если -1.0 у X, то по +0.1 до +0.2 у каждого из 5 остальных (всего +0.5 до +1.0, асимметрично).

### Запись
После каждого опроса / слива:
1. Записать в `STATS.json` поле `reputation.history`: `{"day": N, "event": "...", "delta": +0.8, "reason": "..."}`
2. Обновить `current`.
3. Пересчитать `trend` относительно прошлой записи.

## 2. AFFINITY (близость с Норой)

**Принцип:** личное доверие персонажа к Норе. Скрыто от публики, видно только в STATS POST как доп. слой.

**Шкала:** 0-100. Кумулятивно. Не падает ниже 0.

**Пороги разблокировки:**
- **25%** → DOSSIER (скрытая привычка)
- **50%** → NOTEBOOK PAGE (flashback / прошлое)
- **75%** → короткая STORY (Shadow Preferences)
- **100%** → SHADOW HOOK пост (главный секрет)

См. полные описания: `AFFINITY_UNLOCKS.md` (или поле `unlocks` в `STATS.json`).

### Формулы движения

**Прямой выбор «иду к X» в опросе:**
- +10 к X
- -5 к конкурентам, на которых был бы аналогичный выбор (распределение по обстоятельствам)

**Помощь X через ресурсы Норы:**
- Малая (информация передана): +5
- Значимая (доступ открыт): +10
- Большая (Нора рисковала ради X): +15

**Холодная реакция Норы на X:**
- Игнор в опросе: -5
- Активный отказ / отвержение: -10
- Слив против X (если X понял что это Нора): -15

**Black Velvet слив против X (анонимный, X не подозревает Нору):**
- 0 affinity (репутация двигается, affinity нет)

**Прямой разговор / интимный момент:**
- Лёгкое сближение: +5
- Открытый разговор: +10
- Решающая откровенность: +15 до +20

**Несколько персонажей одновременно (соперничество):**
Если в опросе выбран X, остальные 5 теряют по -2 до -5 affinity в зависимости от контекста ("Нора показала свою сторону").

### Запись
После каждого опроса / взаимодействия:
1. Записать в `STATS.json` поле `affinity.history`: `{"day": N, "event": "...", "delta": +10, "from": "current_value"}`
2. Обновить `current`.
3. Проверить пороги: если current ≥ 25 и unlocks.25.triggered == false → разблокировка, написать пост типа DOSSIER, отметить triggered = true.
4. Аналогично для 50, 75, 100.

## 2.5 СТРАТИФИКАЦИЯ ОПРОСОВ - количество опций

В KM используется **дифференцированное количество опций** в зависимости от типа опроса. Это влияет на дизайн опроса и на интенсивность движения чисел.

| Тип опроса | Опций | Когда | Влияние на STATS |
|------------|-------|-------|------------------|
| **Daily story poll** | 2-3 | Стандартный ежедневный опрос (12:00 / 14:00) | Среднее (±0.3 до ±0.8 reputation, ±5-10 affinity) |
| **Major Choice** | 4 | Раз в фазу, когда вариативность естественна (например, выбор тона слива, направления удара) | Высокое (±1.0 до ±1.5 reputation, ±15 affinity) |
| **PHASE FINAL** | **6** | Финал каждой фазы (Дни 7 / 14 / 21). По одной опции на каждого из шести претендентов | **Драматическое** (±2.0 до ±3.0 reputation для выбранного, ±5-10 reputation у конкурентов; ±20 affinity) |
| **Setup / Pre-story** | 2-4 | Конфигурационные опросы до старта Phase 1 | Параметрические (не двигают reputation/affinity, фиксируют конфигурацию) |

### Phase Final - механика 6 опций

Финал каждой фазы предлагает читателям ВЫБРАТЬ ОДНОГО из шести претендентов. Это центральная механика Reputation Mining.

**Phase 1 финал (День 7):** «Кого подставить первым Black Velvet?»
**Phase 2 финал (День 14):** «Второй слив - какую правду открыть?»
**Phase 3 финал (День 21):** «Голос Норы на коронации - за кого?»

В каждом случае - 6 опций, по одной на претендента:
- 🔘 Адриан
- 🔘 Беатрис
- 🔘 Леон
- 🔘 Дэмиен
- 🔘 Изабелла
- 🔘 Хлоя

Резолюция:
- Победитель (абсолютное большинство или плюрарность) - получает максимальный delta
- Конкуренты - получают каскадный delta (часто противоположный)
- Если две опции равны - применяется правило ничьи (третий путь / двойной удар / отказ)

### Major Choice - примеры

Phase 1 промежуточный (День 4 примерно):
- «Какой тон у первого слива?» (4 опции: намёки / факты / документ / двойной голос)

Phase 2 промежуточный (День 10):
- «Когда обнародовать 7-го претендента?» (4 опции: сейчас / на заседании / через утечку / держать)

## 3. ВЛИЯНИЕ ОПРОСОВ - типовые сценарии

### Тип «На кого направить Black Velvet?» (3 опции, выбор одного)
- Победитель X: репутация X +1.0 до +2.0 (хуже)
- Конкуренты Y, Z: репутация -0.2 до -0.5 каждому (немного лучше на фоне)
- Affinity не двигается (X не знает что Нора стояла за каналом)

### Тип «К кому пойти?» (3 опции, выбор одного)
- Победитель X: affinity X +10
- Конкуренты Y, Z: affinity -3 до -5 каждому
- Репутация не двигается напрямую (это закрытое движение Норы)

### Тип «Кому помочь?» (3 опции)
- Победитель X: affinity X +10, репутация X -0.3 до -0.5 (помощь видна)
- Конкуренты: affinity -3, репутация без изменений

### Тип «Принять / отказать предложение X»
- Принять: affinity X +15, репутация без изменений
- Отказать: affinity X -10, репутация без изменений

### Тип «Что говорить на заседании?» (тон / содержание)
- Зависит от персонажей, которых упоминает заявление. Чужая критика на заседании = их репутация +0.5

### Тип «Кого защитить от слива?»
- Защищённый X: affinity X +5, репутация X -0.3 (выглядит чистым)
- Незащищённый Y: репутация +1.0 (слив проходит), affinity -5

## 4. РАБОЧИЙ ЦИКЛ (после каждого опроса)

```
1. Опрос закрылся → результат от пользователя
2. Записать в POLL_LOG.md
3. Определить deltas по формулам выше
4. Применить к STATS.json:
   - reputation.current и .history для каждого затронутого
   - affinity.current и .history для каждого затронутого
   - пересчитать .trend
5. Проверить пороги affinity (25/50/75/100)
   - Если пройдён - запланировать соответствующий unlock-пост в ближайшие 2-3 пуб.дня
   - Отметить unlocks.X.triggered = true и post_id когда напишем
6. Синхронизировать STATE.md с ключевыми числами (для читаемости)
7. Если конец фазы (День 7 / 14 / 21) - написать STATS POST
```

## 5. STATS POST (раз в фазу или по событию)

**Когда:** концовка фазы (День 7, 14, 21) или после крупного сдвига котировок.

**Что показываем читателю:**
- Таблица котировок претендентов (как DATA SCOREBOARD в VS)
- Affinity скрыто или показано числами (TBD: общественно или нет?)
- 1-3 строки нарративного комментария о движениях

**Решение про публичность Affinity:**
- **Вариант А:** Affinity скрыто, только котировки публичны. Affinity влияет на разблокировки и True Route, читатель узнаёт через разблокированные посты.
- **Вариант B:** Affinity публично - читатель видит «60% Адриан / 40% Леон» как явную метрику.

Рекомендация: **Вариант А.** Скрытое affinity делает разблокировки приятным открытием, не метрической гонкой.
