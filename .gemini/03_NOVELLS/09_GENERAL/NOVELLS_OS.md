# 🧬 NOVELLS OS v1.0

Единый источник истины для производства всех проектов Novells.
Каждый проект - изолированная история. Этот документ задаёт правила и форматы, не контент.

При конфликте с другими файлами - **этот документ выше**. Старые документы (META_TEMPLATES v4.0, MANIFESTO v8.0) сохраняются как архивные источники, но истинные правила - здесь.

---

## 0. ПРИНЦИПЫ

1. **Изолированные проекты.** Каждая новелла - закрытый мир. Никаких мультиверс-кроссоверов, никаких общих персонажей между проектами. Голос, лор, механики - per project.

2. **Опросы ведут истории.** STORY-пост не вводится без прошедшего опроса о персонаже/конфликте. WEEK_ARC и PHASE_ARC - это скелеты возможностей, не предписанные сценарии. См. [[feedback_novells_polls_drive_stories]].

3. **Время в новеллах живёт отдельно.** Реальные даты публикации ≠ нарративное время. Каждый проект имеет свою временную шкалу. См. [[feedback_novells_time]].

4. **Голос проекта зафиксирован.** Lexicon, ритм, форматы - в `VOICE_LOCK.md` каждого проекта. Это позволяет писать любой моделью без потери стиля.

5. **Числа двигаются опросами.** Affinity, Reputation, котировки - не выдумываются на ходу. Каждый опрос имеет заранее заданное влияние на параметры.

6. **Аудит перед написанием.** Каждая сессия начинается с инвентаризации: что опубликовано, какие опросы прошли, кто опрошен, кто нет, где в структуре сезона. См. [[feedback_novells_audit_before_writing]].

7. **Без эм-тире. Только дефис.** Универсально. См. [[feedback_dashes_universal]].

## 1. СТРУКТУРА СЕЗОНА

### Размер
**21 публикационный день** = **3 Фазы × 7 дней**.

### Эластика времени
Внутри 21 пуб.дня каждый проект имеет **свою временную шкалу**. Зафиксирована в `SEASON_1_ROADMAP.md` каждого проекта.

Примеры:
- **Vienna Special:** 21 пуб = 7 нарративных дней (Eurovision-неделя)
- **Kingmaker:** эластика (1:1 в Phase 1 и 3, ~6 недель в Phase 2)
- **Orchid:** TBD (предположительно сжатие до одной ночи heist)
- **Order:** TBD (предположительно 21 ночь, 1:1)

### Темп публикаций (стандарт)
```
09:45  VERDICT - итоги вчера, анонс дня
12:00  STORY + POLL #1
14:00  STORY + POLL #2
17:00  PERSONA / SUPPORTING POST
20:00  CLIFFHANGER / STORY без опроса
21:00  STATS / SCOREBOARD (по необходимости)
```

В дни особых событий (финалы, повороты) - адаптация.

## 1.5 СЕЗОННАЯ АРХИТЕКТУРА И РОТАЦИЯ (тактика «чередуем сезоны»)

Проекты идут НЕ один до конца, а ЧЕРЕДУЮТСЯ по сезонам (round-robin) в едином канале: один сезон проекта за раз = главная активная история; остальные в это время - только тизеры/досье на хэндофф.

**Бюджеты сезонов (решено 06.06.2026):**
- **Kingmaker - ТРИЛОГИЯ (3):** S1 Интеррегнум → S2 корона-ловушка/кто правит на самом деле → S3 развязка.
- **Orchid - ДУОЛОГИЯ (2):** S1 дело «Орхидея» + романвыбор → S2 последствия/крупнее + проверка любви.
- **Eleyia - ДЛИННАЯ САГА (~7):** 10/11/12 класс + 4 года универа.

**Порядок ротации** (тон чередуется: тёмный → гламур → эмоция): **Kingmaker → Orchid → Eleyia**, повторяя.

| Круг | Kingmaker | Orchid | Eleyia | Новый проект |
|------|-----------|--------|--------|--------------|
| 1 | S1 (идёт) | S1 | S2 | - |
| 2 | S2 | S2 (финал) | S3 | - |
| 3 | S3 (финал) | завершён | S4 | новый S1 |
| 4+ | завершён | - | S5 → S7 | новый S2+ |

KM завершается на круге 3, Orchid на круге 2; освобождённые слоты → «третий/новый проект» (см. CORE_BRAIN). Eleyia - якорь до S7. Хэндофф между сезонами: ~7 дней тизера следующего проекта доп-слотами (шаблон: `ELEYIA/02_SYSTEM/S2_PRELAUNCH_PLAN.md`).

**ВЫБОР НОВОГО ПРОЕКТА на освобождённый слот - «Пилот-голосование» (опросы ведут даже выбор истории):**
- **Банк идей (~13):** 8 «тяжёлых» (KM, Donor, Horizon, Orchid, Order, Code, Anthropos, Eleyia) + 8 «лайт» (Оранжерея, Ночной поезд, Открытки, Пекарня, Персуазия, Амели, Снегурочка, Красавица и Чудовище) - см. `PROJECT_MANIFESTO.md`, `PROJECT_IDEAS_LIGHT.md`.
- **Шортлист 3-4 финалиста** (не все 13 - паралич выбора): автор курирует по готовности + контрасту тона (балансируя тяжёлое/лайт под соседей в ротации) + настроению момента. Опц. ещё пара как «лонглист»-тизеры для вкуса.
- **Формат:** тизер-пич-карточки (как мультивселенные-превью Eleyia S1): жанр / хук / протагонист / одна фраза / сигнатурная техника / арт-настроение. Затем финальный опрос по 3-4.
- **КОГДА (важно):** вся подготовка идёт ВО ВРЕМЯ РАБОТАЮЩЕГО сезона ДРУГОЙ новеллы - доп-слотами, растянуто по сезону (организованным параллельным треком, не хаотично):
  - **Этап A (выбор)** - раньше/в середине того сезона: анонсы кандидатов + пилот-опрос.
  - **Этап B (прогрев победителя)** - ближе к финалу/хэндоффу того сезона: анонс + конфиг-опросы + досье.
  - К концу того сезона победитель и ВЫБРАН, и ПРОГРЕТ → стартует в освободившийся слот без паузы.
- **После победы:** активация проекта (папка + BIBLE/VOICE_LOCK/CANON/ROADMAP/STATE), назначается бюджет сезонов, входит в ротацию.

**ПОЛНАЯ ПОСЛЕДОВАТЕЛЬНОСТЬ ЗАПУСКА НОВОЙ НОВЕЛЛЫ (два этапа - помнить!):**
*Этап A - ВЫБОР:*
1. **Краткие анонсы кандидатов** (3-4) - тизер-пич-карточки шортлиста (коротко: что за новелла, хук).
2. **Пилот-опрос** - читатели выбирают одну.
*Этап B - ПРОГРЕВ победителя (как прелюд Orchid):*
3. **Полноценный анонс** выбранной новеллы (мир, протагонист, ставка).
4. **Конфиг-опросы** (прогрев, ~5 дней): **ПЕРВЫЙ опрос - ПОЛ ГЛАВНОГО ГЕРОЯ** (читатель определяет до старта новеллы - это основа), затем спектр/ориентация, легенда, стиль, первая цель, союзник и т.п.
5. **Знакомство с героями** - карточки-досье (видовые черты где есть + глубина анкеты: Суперцель/мотивация/слабость/речь).
6. **Старт сезона** (День 1).
> НЕ путать: сначала коротко рассказать о кандидатах + опрос-выбор (A), и только ПОТОМ - анонс победителя + конфиг-опросы + досье героев (B).

## 2. ТИПЫ ПОСТОВ (FORMATS)

### Ядро (используются ежедневно)

**VERDICT** (09:45) - итоги опросов + интерпретация + анонс дня. Атмосферно, не перечислением. См. формат в [[META_TEMPLATES.md]] раздел 3.

**STORY + POLL** (12:00 / 14:00) - сцена + 2-3 опции выбора для читателя. Опции должны быть **значимо разными** (никаких «да / тоже да»). Сцена пишется в нарративном времени проекта.

**CLIFFHANGER** (20:00) - сцена без опроса. Наблюдение, документ, телефонный экран. Готовит следующий день.

### Дополнительные

**PERSONA** - карточка персонажа. Не сюжет, представление. Обычно 17:00 в KM, в других проектах - по календарю.

**DOSSIER** - утечённый документ. Email, контракт, медсправка, отчёт. Лор-плотность, визуально другой формат текста.

**NOTEBOOK PAGE** - страница из блокнота ГГ. Рукописный стиль (имитируется через шрифт/типографику). Наброски, зачёркивания, вопросы себе.

**BLACK VELVET LEAK** (KM) / **CHANNEL SIX** (VS) / эквивалент per project - анонимная утечка или радио-перехват. Одна цитата + контекст + кто читает.

**AUDIO TEMPLATE** - формат «голосового сообщения в тексте». Таймкоды, паузы, фоновый шум. Готовится к настоящему аудио.

**TRUE ROUTE FRAGMENT** - скрытый кусок, доступный только при определённой комбинации выборов. Помечается отдельно в `TRUE_ROUTE.md` проекта.

### Системные

**STATS / SCOREBOARD** - публичная сводка чисел: котировки в VS, Reputation Mining в KM, эквивалент per project. Раз в фазу минимум, чаще - по необходимости.

**MAJOR CHOICE / VERDICT финала фазы** - конец Phase 1/2/3 - усиленный VERDICT с итогами фазы и переходом.

## 3. ОПРОСЫ (POLL MECHANICS)

### Базовые правила

- **2-3 опции.** Не 4+, не 1.
- **Опции значимо разные.** Не «делай X / делай X+1».
- **Третий путь при ничьей.** Когда зал делится 50/50, ГГ изобретает третий путь - комбинируя или отвергая оба. Это **не отговорка**, это явный нарративный приём (см. Алекс/Марко тихий блок, Алекс/Эрик Клавис, Алекс/Клара).
- **Опрос закрывается** в 20:00 (или согласно проектному ритму).

### Цикл

```
Опрос ставится → читатели голосуют → опрос закрывается → 
результаты заносятся в POLL_LOG.md → 
числа двигаются (affinity, reputation, котировки) → 
следующий пост пишется на основе результата
```

### Что нельзя

- Писать STORY на день X с новым конфликтом без опроса, который мог бы привести к нему. См. [[feedback_novells_polls_drive_stories]].
- Делать ретроактивные изменения опубликованных опросов.
- Выдумывать движение чисел без формулы.

## 4. ГОЛОС ПРОЕКТА (VOICE LOCK)

Каждый проект имеет `02_SYSTEM/VOICE_LOCK.md` со структурой:

```markdown
# [PROJECT] VOICE LOCK

## Временная шкала
[21 пуб.день = X нарративных. По фазам если эластика.]

## Общий регистр
[жанр, эмоция, перспектива, среда, сравнение с другими проектами]

## Лексикон ДА (50-100 слов)
[слова и термины, которые часто используем]

## Лексикон НЕТ (запрещённые)
[слова, которые ломают атмосферу]

## Обязательные приёмы (5-10)
[например: точные числа, таймкоды, короткие предложения, латынь, etc.]

## Запрещённые приёмы (5-10)
[например: эмодзи внутри текста, восклицания, наречия степени]

## Ритм
[длина предложений, абзацы, паузы]

## Прозовая техника / Нарративная рамка
[Сигнатурный приём проекта. ОБЯЗАТЕЛЬНЫЙ раздел.
Не каждый проект пишется одинаково - даже при общей структуре. Каждый проект имеет
**одну сигнатурную технику**, которая работает через весь сезон и отличает его от других:
- KM: Sub Rosa (двухслойная сцена - видимое + скрытое)
- VS: Многокамерный POV (для cliffhanger/кульминаций)
- Orchid: План vs Реальность (для heist-битов)
- Donor: Литургический ритм + Heart Rate (для пиков)
- Order: Свидетельство Суда Почвы (для финальных ночей)

- Anthropos: Сенсорная инвентаризация (для межвидовых моментов)
- Eleyia: Синестезия (всегда)

Раздел описывает: принцип, формы реализации (2-3 варианта чтобы не было формулой),
правила применения, где НЕ применять, образец полного применения.]

## Шаблоны по типу поста
[Скелеты VERDICT, STORY+POLL, PERSONA, CLIFFHANGER, специфичные форматы проекта]

## Образцы (3-5 эталонных постов)
[ссылки на лучшие посты проекта]

## Визуальный голос
[Палитра промптов, кадрирование, запреты для изображений]

## Чек-лист перед коммитом
[Бинарные проверки ✅/❌, включая Sub Rosa-эквивалент для STORY]
```

### Текущие проекты

- **Vienna Special:** требует написания (доделать после финала)
- **Kingmaker:** требует написания (до старта Phase 1)
- **Orchid, Donor, остальные:** до старта своих сезонов

## 5. МЕХАНИКИ (per project)

### Reputation Mining (KM)
Каждый претендент имеет котировку. Опросы и Black Velvet сливы двигают её. Котировки видны в STATS POST раз в фазу минимум.

### Affinity / True Route (универсально, активируется в KM первым)

Пороги:
- **25%** → Скрытая привычка (DOSSIER)
- **50%** → Flashback (NOTEBOOK PAGE)
- **75%** → Shadow Preferences (короткая STORY)
- **100%** → Теневой Хук (главный секрет персонажа)

Финал имеет несколько концовок, доступных по комбинации аффинити.

### Black Velvet / Channel Six / эквивалент
Канал утечек - инструмент протагониста. Слив имеет цель, тональность, последствие на котировки.

### Stats хранение
`02_SYSTEM/STATE.md` или отдельный `STATS.json` - источник чисел. Не выдумываются на лету.

## 6. ПРОМПТЫ ДЛЯ ИЗОБРАЖЕНИЙ (REVE.AI)

Платформа: **app.reve.com**. Не Midjourney. Без флагов `--ar --v --style --s`.

### Формула
```
[CHARACTER TAG с ИМЕНЕМ] + [scene + environment + lighting] + [quality tags] + [aspect ratio]. No text, no logos.
```

### Имя персонажа - ВСЕГДА
Не «young woman» - писать «Theodora, late twenties Serbian woman». Не «professional woman» - «Alex Weiss, 32-year-old». Это для консистентности образа на разных постах.

### Базовые quality tags (всегда)
`Photorealistic, 8k, cinematic style, high contrast shadows, vibrant rich colors, cinematic color grading, high-end fashion editorial photography, shot on Kodak Portra 800, model-like features, editorial model appearance, perfect symmetrical face`

### Per-project палитра
- **Kingmaker:** `Quiet Luxury Noir, dark interior, candlelight, obsidian and gold palette`
- **Vienna Special:** `backstage atmosphere, cold halogen lighting, documentary photography style`
- Остальные - задать в `VOICE_LOCK.md` проекта при старте сезона.

### Aspect ratio
Текстом: `Square frame 1:1` / `Vertical frame 9:16` / `Horizontal frame 16:9`.

### Брендинг
В Novells - **без брендинга** (никаких подписей, логотипов, имени канала на изображении). Финал: `No text, no logos`.

См. [[feedback_novells_prompts]], [[feedback_novells_prompts_reve]].

## 9. ЗАПРЕТЫ (ЖЁСТКИЕ)

- Эм-тире (-) - только дефис (-). См. [[feedback_dashes_universal]].
- Брендинг в Novells (нет логотипов, нет имени канала на изображениях).
- Midjourney-флаги в промптах (нет `--ar`, `--v`, `--style`, `--s`).
- Сюжетные посты без прошедшего опроса о персонаже/конфликте.
- Реальные даты в нарративных файлах и постах (только в POSTING_SCHEDULE.md).
- Кроссоверы между проектами (изолированные миры).
- Перезапись или удаление утверждённых концовок без согласия пользователя.

## 10. РАБОЧИЙ ЦИКЛ ДНЯ

```
1. АУДИТ - запустить `tools/audit.sh <project>` (см. [[feedback_novells_audit_before_writing]])
   - Скрипт выводит: публикации за 7 дней / STATE / последние опросы /
     STATS (если есть) / временную шкалу / напоминания
   - Дополнительно проверить ручно:
     - Какие персонажи опрошены, какие нет?
     - Что напрашивается на сегодня?

2. ПЛАН ДНЯ
   - Предложить пользователю структуру дня
   - Подтвердить нарративный темп (особенно в эластических фазах)
   - Получить «да» перед написанием

3. СИСТЕМА
   - Обновить POLL_LOG с результатами вчера
   - Обновить STATE / STATS с движением чисел
   - (Sonnet 4.6)

4. НАРРАТИВ
   - Написать VERDICT
   - Написать STORY+POLL слоты
   - Написать CLIFFHANGER / STATS
   - (Opus 4.7)

5. ПРОВЕРКА
   - Эм-тире = 0
   - Имена персонажей в промптах
   - Опросы валидны (2-3 опции, значимо разные)

6. КОММИТ
   - git commit с описательным сообщением
   - Не пушим без явной просьбы пользователя
```

## 11.5 СТАНДАРТЫ ДЛЯ ВСЕХ ПРОЕКТОВ (текущих и БУДУЩИХ)

Эти правила наследует КАЖДЫЙ проект-новелла, включая новые. У каждого проекта - свой `02_SYSTEM/CANON.md` с разделами ниже.

- **Тональный баланс (обязательно):** не «только плохо всё». В каждом сезоне держать вперемешку с конфликтом: (1) общая проблема + ЕЁ РЕШЕНИЕ, (2) любовные/романтические отношения, (3) семейные дела (или «семья по выбору»), (4) хорошие моменты (победы, юмор, дружба, передышки). На каждый тёмный беат - светлый.
- **РОМАНТИКА - ЖАНРОВОЕ ЯДРО (обязательно ВЕЗДЕ; усилено 14.06.2026):** CORE - канал РОМАНТИЧЕСКИХ новелл. В КАЖДОМ проекте (текущем, будущем, идее банка, спешле, лайте) романтика - двигатель, а не фон: минимум одна живая романтическая линия (обычно 2-3 LI), высокая плотность любовных беатов, романтический выбор как сердце опросов. Жанр-обёртка (хоррор/триллер/детектив/сказка/фолк) обслуживает любовную историю, не наоборот. Идея без романтического двигателя НЕ запускается (ядро-чек инкубатора). LI ≤35 по видимому возрасту. Расширять каст при нужде.
- **Возраст любовных интересов 35 и младше** (для нелюди - по видимому возрасту).
- **Все заведённые герои появляются** в повествовании - никаких «мёртвых душ».
- **ВТОРОЙ КРУГ ГЕРОЕВ (заведено 11.06.2026):** главного каста (ГГ + LI + ключевые сюжетные) МАЛО - мир не должен крутиться вокруг одних и тех же лиц. У каждого проекта - `02_SYSTEM/SUPPORTING_CAST.md`: 4-6 живых второстепенных героев с именем, функцией, речевым тиком и CHARACTER TAG (имена-в-промптах действует и на них). Правила: (1) вводить по одному, сценой с функцией - не списком; (2) второй круг ДВИГАЕТ сюжет (источник информации/осложнение/тепло), а не декорирует; (3) лучшие - повышаются (второй круг -> сюжетный каст следующего сезона); (4) НЕ LI по умолчанию (возрастной кап LI на них не действует), романтика - только осознанным решением; (5) появление 1 героя второго круга минимум раз в 2-3 Главы. Безымянная массовка («крупье», «официант») остаётся фоном - второй круг это те, кто получает имя и возвращается. **(6) Готовый PORTRAIT PROMPT каждого героя второго круга хранится в SUPPORTING_CAST рядом с тегом** (полный сольный промпт в фактуре проекта; вносится в систему ДО первого появления героя - чтобы образ можно было посмотреть и одобрить заранее; стандарт заведён 12.06.2026).
- **Истории не повторяют сюжетные линии** друг друга (каждый проект - свой жанр/движок).
- **ИНКУБАТОР ИДЕЙ + СИСТЕМА ОТБОРА (заведено 14.06.2026, решение пользователя):** приток НОВЫХ идей (`IDEA_INCUBATOR.md`, воронка сырая→ядро-чек→мини-бриф) + единый обзор всех миров (`IDEA_INDEX.md`: регион×тон×жанр×стадия) + система отбора от идеи до эфира (`SELECTION_SYSTEM.md`). **Стадии готовности S0 сырая → S1 бриф → S2 каркас → S3 папка → S4 эфир.** Приоритет: активная ротация → папочные S2+ → инкубатор (готовность БЬЁТ новизну, недострой не плодим). Читателям выбор - через ПИЛОТ-ГОЛОС (шортлист 3-4 мира S2+ на NEW-слот, критерии: тон-контраст/жанр-регион-разнообразие) + фоновый ОПРОС ИНТЕРЕСА (`#ждущиемиры`). Чек концепта (обязателен для каждого нового мира/сезона/спешла): (1) назвать троп, на котором стоим («боги-корпорации», «вампирский суд», «избранный, которого система не видит»…); (2) назвать ПЕРЕВОРОТ - чем наше ядро глубже/страннее тропа (онтология, цена, телесность, инверсия избранности); (3) если переворота нет - концепт не запускаем, дорабатываем. Переворот фиксировать в BRIEF/CANON секцией «ЯДРО», секретные перевороты - локом «не публиковать».

## 11.7 TELEGRAM-НАТИВНЫЕ МЕХАНИКИ ВОВЛЕЧЕНИЯ

Инструменты мессенджера, усиливающие интерактив без ботов/автоматизации. Наша модель - КОЛЛЕКТИВНЫЙ голос → ЕДИНЫЙ таймлайн (не индивидуальное ветвление), единый канал, ручное ведение. Эти механики работают поверх неё.

### A. Реакции как экспресс-микроголосование
- В дополнение к опросам (закрытие 20:00) - быстрые ТАКТИЧЕСКИЕ выборы реакциями: ограничить набор канала до 2-4 эмодзи, привязать каждую к действию (напр. 👍 действовать / 🔥 рискнуть / 🧊 выждать). Окно - короткое (час-два), считается вручную, ведёт мелкий беат между крупными опросами.
- Реакции как мягкий нудж affinity/репутации (точечно), НЕ как полная RPG-валюта - основные числа по-прежнему двигают опросы.
- **Реакц-слот - СТАНДАРТ КАЖДЫЙ ДЕНЬ (усилено 14.06.2026):** 1 реакц-беат ежедневно (~15:00, между опросами 13/16), не опционально. Это дешёвая по тексту точка агентности (реакция на существующий пост, не новый пост) - наращивает вовлечение БЕЗ наращивания числа постов. Максимум 1/день (не конкурировать с опросами; больше - усталость).
- **Реакц-порог как бонус:** «наберём N 🔥 - выложу следующий пост раньше/сегодня ночью». Геймификация ожидания, разгоняет охват.

### A2. ВАРИАТИВНЫЙ РИТМ - пики vs будни (внедрено 14.06.2026)
Число постов НЕ растёт линейно «больше всегда» (потолок Telegram: 7-8+/день = мьют/отписки). Вместо этого ритм дышит по драматургии:
- **Будни (проходные Главы):** базовые 5-6 постов + 2 опроса + 1 реакц-слот. Держать ровно, не раздувать.
- **ПИКИ (клифф-Глава блока, главный твист, финал, хэндофф):** усиливать - доп STORY-слот и/или 3-й опрос и/или теневой доп-пост (§A3). «Больше там, где жарко», не везде.
- **Решать по метрикам:** охват растёт без отписок - можно осторожно добавить в пик; начали мьютить - на потолке, убрать. Главный рычаг роста - ГЛУБИНА вовлечения (реакции/спойлеры/OOC), не число.

### A3. ТЕНЕВОЙ ДОП-СЛОТ (шаблон для кульминаций; внедрено 14.06.2026)
Лёгкий доп-пост параллельной микро-линии для пиковых дней (наследник BV-механики KM, но универсально). Не основной слот, не ломает ритм - «второе дно» дня:
- **Что это:** короткий пост (~1-2 мин) от иного «голоса»/ракурса - анонимный наблюдатель, улика, перехваченное сообщение, взгляд антагониста, спойлер-слой под катом.
- **Когда:** только пики (клифф блока/твист/финал/хэндофф), не каждый день. ~21:00 (после клиффа 20:00, последовательно) или встроить в спойлер существующего поста.
- **Зачем:** догоняет охват в кульминации, даёт интригу/форшэдоу, не требуя полноценной Главы-нагрузки.
- **Формат по проекту:** Orchid - «перехват» (записка/камера Софи/ход Валентины); KM S2 - новый Black Velvet (выпуск «СЧЁТ»); Eleyia - «канал Директората»/слух; Белая Дама - дайна-предзнаменование/шёпот озера. Свой ярлык, без кросс-упоминаний.

### B. Спойлер-слой (скрытый текст)
- Telegram-спойлер для скрытого слоя сцены: **Sub Rosa («Под этим:»)**, редактуры/POSTSCRIPTUM Black Velvet, улики, альтернативные исходы, секретные параметры. Читатель раскрывает по желанию - сохраняет интригу и даёт «второе дно».
- Применять к: загадкам/детективным веткам, скрытым последствиям выбора, тизеру разгадки до её часа.
- Не прятать ключевую сюжетную информацию целиком - спойлер для ДОПслоя, не для основного текста.

### C. Связанная группа-обсуждение (OOC)
- Это НЕ второй канал (правило единого канала цело) - это комментарии под постами. Зона IC = канал (чистое повествование), OOC = обсуждение/теории/реакции.
- Использовать активно: поощрять теории, отвечать в комментах, мини-события в чате между постами для удержания.

### D. Тизеры и дискаверабилити
- Тизер-карточки: цитата-вырезка из поста + эстетичный арт + локальные мемы комьюнити.
- **Telegram Stories канала:** тизер главы / анимированный спрайт-арт / цитата с кликабельной ссылкой на пост; короткое окно показа - лидогенерация и удержание.
- Дискавери-теги рядом с проектными: #книгаигра #ролевая #интерактив (для внутреннего поиска), не ломая фирменные хэштеги проекта.
- Рост через агрегаторы (@gamebooks, @role_play_in_tg) - размещение анонсов/досье ключевых персонажей.

### E. Вовлечение читателей
- Именные роли активным участникам, публичное поощрение за разгадки, мини-события в чате - эмоциональная связь с миром.
- **POV-посты антагониста / morally-grey героя:** изредка - сцена/дневник от лица «злодея» или неоднозначного героя. Читатель начинает его оправдывать → споры в комментах → органический охват. У нас материал есть (Изабелла, Дэмиен, Канцлер в KM; Лоран/Николя в Orchid; Оэрон/Феликс в Eleyia). Опираться на CHARACTER_DEPTH (мотивация/слабость).
- **In-character Q&A:** читатели «задают вопрос персонажу» в комментах, автор отвечает ОТ ЛИЦА героя (по его речевой манере из CHARACTER_DEPTH). Диалог между постами, держит привязанность.
- **Кружочки от лица персонажа (опц.):** 20-30-сек видеомонолог перед эмоциональной сценой = озвучка новеллы, поднимает просмотры. Использует голос/радио-бэкграунд автора. Точечно, для пиков.
- **Стикерпак/кастом-эмодзи с персонажами:** свой набор → читатели репостят → органическое распространение.

### F. Музыкальный саундтрек главы (наш differentiator)
- Каждая глава/сцена выходит с **трек-настроением**: «эта сцена звучит как [трек]». Использует музыкальный/Евровиденье-бэкграунд автора (связка с YourVision/радио).
- Читатель ассоциирует музыку с персонажем/сценой → attachment растёт. Уникально для жанра, мало кто делает.

### G. Читательская «Библия»/Навигатор (закреп)
- Для длинных историй - закреплённый пост или Telegraph-страница: карта персонажей (арт + одна фраза-кредо каждого = Суперцель из CHARACTER_DEPTH) + таймлайн событий + глоссарий мира.
- Чтобы новый подписчик не терялся к 5-й серии. ВНУТРИпроектная (не общая на все Новеллы).
- **ДВА уровня навигаторов:**
  - **Навигатор КАНАЛА** (оглавление: что идёт / что было / что впереди + как устроено). Шаблон-источник: `09_GENERAL/CORE-10.05-NAVIGATOR.md`. Проекты ИЗОЛИРОВАНЫ - без кроссоверов.
  - **Навигатор НОВЕЛЛЫ** (читательская Библия активной истории: карта героев с кредо, правила, словарь). В `<ПРОЕКТ>/04_CONTENT/.../NAVIGATOR-PINNED`.
- **ПРАВИЛО ПЕРЕНОСА (на старте КАЖДОГО нового сезона):** создаём новую ДАТИРОВАННУЮ инстанцию навигатора канала `09_GENERAL/04_CONTENT/.../NV-<дата>-NAVIGATOR.md` (из шаблона, С ИЗМЕНЕНИЯМИ под новый сезон) и ПЕРЕЗАКРЕПЛЯЕМ её; параллельно (пере)закрепляем Навигатор-Библию новой активной новеллы. Так навигатор «переезжает» вперёд каждый сезон и не забывается. (Заведено 09.06.2026.)
- **РИТМ ОБНОВЛЕНИЯ БИБЛИИ (заведено 11.06.2026):** Навигатор-Библию активной новеллы РЕДАКТИРУЕМ (Telegram edit закрепа) **каждые ~5 Глав** и на границах сюжетных блоков: дописываем выданный лор (новые карточки героев/мира из лор-очереди), помечаем прогресс сезона («идёт блок II»), обновляем словарь. Так новый подписчик с Главы 12 видит актуальную карту, а не стартовую. Чек: при закрытии Глав 5/10/15/20 - пункт «обновить Библию» в дневной рутине.

### H. Лор-слой в доп-слотах ведущей новеллы (СТАНДАРТ)
Доп-слоты единого канала во время РАБОТАЮЩЕГО сезона ведущей новеллы заполняются **лор-контентом** этой же новеллы (не параллельной историей). Это углубляет мир без перегрузки основной 5-постовой линии и даёт «второе дно» для теорий в комментах. Четыре типа карточек:
- **Карточки героев** (DOSSIER-формат) - портрет по CHARACTER TAG + Суперцель/слабость/речь из CHARACTER_DEPTH. Сначала закрыть весь каст, потом не плодить новые лица.
- **Карты мира** - по карточке на ключевой термин/локацию из GLOSSARY (предметный/атмосферный промпт, без героя): что такое MacGuffin, узлы, фракции, точки входа, фоновые угрозы.
- **Прошлое героев** (flashback-карточки) - синхронно с affinity (25% досье → 50% страница-флешбэк → 75% story). Дозированно. Мистерии НЕ раскрывать заранее (фактура намёками, ответ держим - см. CANON проекта).
- **Глоссарий-карточки** - «термин дня», короткие.

Правила лор-слоя:
- **Темп:** ~1 лор-доп-слот в день (или через день). Не перегружать поверх 5 основных постов и не конкурировать с опросами 13:00/16:00.
- **Очередь лор-слотов** ведётся в `STATE.md` проекта (раздел «доп-слоты: лор-очередь») - что выдано, что следующее.
- **Без опросов** (если иное не задумано) и **без кросс-проектных упоминаний** (раздел 0).
- **Хэндофф:** в хвосте сезона (~последняя неделя) лор-слоты переключаются на ПРОГРЕВ следующего проекта (его карточки/мир) - лор текущей новеллы к этому моменту в основном выдан. См. 11.5 / последовательность запуска.
- Связка с G: выданные лор-карточки складываются в закреплённую «Библию»/Навигатор проекта.

### НЕ берём (другая модель)
- Гиперссылочное ветвление «книга-игра» (t.me/c/.../...) на каждого читателя - у нас коллективный голос. Внутренние ссылки только для НАВИГАЦИИ (рекапы, досье), не для ветвления.
- A/B-параллельные ветки (два поста-версии, что сходятся) - у нас коллективный единый таймлайн; иллюзию выбора даёт multi-select при ничьей, не параллельные посты.
- RP-механики соролевиков (отыгрыш читателями персонажей, анкеты участников) - у нас авторская новелла; берём только лёгкое вовлечение.
- **Общая вселенная/кроссоверы между проектами** - проекты ИЗОЛИРОВАНЫ (см. раздел 0). Связанный лор и теории - ВНУТРИ одного проекта, не между.
