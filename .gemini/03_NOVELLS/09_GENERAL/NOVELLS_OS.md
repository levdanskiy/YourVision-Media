# 🧬 NOVELLS OS v1.0

Единый источник истины для производства всех проектов Novells.
Каждый проект - изолированная история. Этот документ задаёт правила и форматы, не контент.

При конфликте с другими файлами - **этот документ выше**. Старые документы (META_TEMPLATES v4.0, MANIFESTO v8.0) сохраняются как архивные источники, но истинные правила - здесь.

---

## 0. ПРИНЦИПЫ

1. **Изолированные проекты.** Каждая новелла - закрытый мир. Никаких мультиверс-кроссоверов, никаких общих персонажей между проектами. Голос, лор, механики - per project.

2. **Опросы ведут истории.** STORY-пост не вводится без прошедшего опроса о персонаже/конфликте. WEEK_ARC и PHASE_ARC - это скелеты возможностей, не предписанные сценарии. См. [[feedback_novells_polls_drive_stories]].

3. **Время в новеллах живёт отдельно.** Реальные даты публикации ≠ нарративное время. Каждый проект имеет свою временную шкалу. См. [[feedback_novells_time]].

4. **Голос проекта зафиксирован.** Lexicon, ритм, форматы - в `VOICE_LOCK.md` каждого проекта. Это позволяет писать любой моделью без потери стиля.

5. **Числа двигаются опросами.** Affinity, Reputation, котировки - не выдумываются на ходу. Каждый опрос имеет заранее заданное влияние на параметры.

6. **Аудит перед написанием.** Каждая сессия начинается с инвентаризации: что опубликовано, какие опросы прошли, кто опрошен, кто нет, где в структуре сезона. См. [[feedback_novells_audit_before_writing]].

7. **Без эм-тире. Только дефис.** Универсально. См. [[feedback_dashes_universal]].

## 1. СТРУКТУРА СЕЗОНА

### Размер
**21 публикационный день** = **3 Фазы × 7 дней**.

### Эластика времени
Внутри 21 пуб.дня каждый проект имеет **свою временную шкалу**. Зафиксирована в `SEASON_1_ROADMAP.md` каждого проекта.

Примеры:
- **Vienna Special:** 21 пуб = 7 нарративных дней (Eurovision-неделя)
- **Kingmaker:** эластика (1:1 в Phase 1 и 3, ~6 недель в Phase 2)
- **Orchid:** TBD (предположительно сжатие до одной ночи heist)
- **Order:** TBD (предположительно 21 ночь, 1:1)

### Темп публикаций (стандарт)
```
09:45  VERDICT - итоги вчера, анонс дня
12:00  STORY + POLL #1
14:00  STORY + POLL #2
17:00  PERSONA / SUPPORTING POST
20:00  CLIFFHANGER / STORY без опроса
21:00  STATS / SCOREBOARD (по необходимости)
```

В дни особых событий (финалы, повороты) - адаптация.

## 2. ТИПЫ ПОСТОВ (FORMATS)

### Ядро (используются ежедневно)

**VERDICT** (09:45) - итоги опросов + интерпретация + анонс дня. Атмосферно, не перечислением. См. формат в [[META_TEMPLATES.md]] раздел 3.

**STORY + POLL** (12:00 / 14:00) - сцена + 2-3 опции выбора для читателя. Опции должны быть **значимо разными** (никаких «да / тоже да»). Сцена пишется в нарративном времени проекта.

**CLIFFHANGER** (20:00) - сцена без опроса. Наблюдение, документ, телефонный экран. Готовит следующий день.

### Дополнительные

**PERSONA** - карточка персонажа. Не сюжет, представление. Обычно 17:00 в KM, в других проектах - по календарю.

**DOSSIER** - утечённый документ. Email, контракт, медсправка, отчёт. Лор-плотность, визуально другой формат текста.

**NOTEBOOK PAGE** - страница из блокнота ГГ. Рукописный стиль (имитируется через шрифт/типографику). Наброски, зачёркивания, вопросы себе.

**BLACK VELVET LEAK** (KM) / **CHANNEL SIX** (VS) / эквивалент per project - анонимная утечка или радио-перехват. Одна цитата + контекст + кто читает.

**AUDIO TEMPLATE** - формат «голосового сообщения в тексте». Таймкоды, паузы, фоновый шум. Готовится к настоящему аудио.

**TRUE ROUTE FRAGMENT** - скрытый кусок, доступный только при определённой комбинации выборов. Помечается отдельно в `TRUE_ROUTE.md` проекта.

### Системные

**STATS / SCOREBOARD** - публичная сводка чисел: котировки в VS, Reputation Mining в KM, эквивалент per project. Раз в фазу минимум, чаще - по необходимости.

**MAJOR CHOICE / VERDICT финала фазы** - конец Phase 1/2/3 - усиленный VERDICT с итогами фазы и переходом.

## 3. ОПРОСЫ (POLL MECHANICS)

### Базовые правила

- **2-3 опции.** Не 4+, не 1.
- **Опции значимо разные.** Не «делай X / делай X+1».
- **Третий путь при ничьей.** Когда зал делится 50/50, ГГ изобретает третий путь - комбинируя или отвергая оба. Это **не отговорка**, это явный нарративный приём (см. Алекс/Марко тихий блок, Алекс/Эрик Клавис, Алекс/Клара).
- **Опрос закрывается** в 20:00 (или согласно проектному ритму).

### Цикл

```
Опрос ставится → читатели голосуют → опрос закрывается → 
результаты заносятся в POLL_LOG.md → 
числа двигаются (affinity, reputation, котировки) → 
следующий пост пишется на основе результата
```

### Что нельзя

- Писать STORY на день X с новым конфликтом без опроса, который мог бы привести к нему. См. [[feedback_novells_polls_drive_stories]].
- Делать ретроактивные изменения опубликованных опросов.
- Выдумывать движение чисел без формулы.

## 4. ГОЛОС ПРОЕКТА (VOICE LOCK)

Каждый проект имеет `02_SYSTEM/VOICE_LOCK.md` со структурой:

```markdown
# [PROJECT] VOICE LOCK

## Временная шкала
[21 пуб.день = X нарративных. По фазам если эластика.]

## Общий регистр
[жанр, эмоция, перспектива, среда, сравнение с другими проектами]

## Лексикон ДА (50-100 слов)
[слова и термины, которые часто используем]

## Лексикон НЕТ (запрещённые)
[слова, которые ломают атмосферу]

## Обязательные приёмы (5-10)
[например: точные числа, таймкоды, короткие предложения, латынь, etc.]

## Запрещённые приёмы (5-10)
[например: эмодзи внутри текста, восклицания, наречия степени]

## Ритм
[длина предложений, абзацы, паузы]

## Прозовая техника / Нарративная рамка
[Сигнатурный приём проекта. ОБЯЗАТЕЛЬНЫЙ раздел.
Не каждый проект пишется одинаково - даже при общей структуре. Каждый проект имеет
**одну сигнатурную технику**, которая работает через весь сезон и отличает его от других:
- KM: Sub Rosa (двухслойная сцена - видимое + скрытое)
- VS: Многокамерный POV (для cliffhanger/кульминаций)
- Orchid: План vs Реальность (для heist-битов)
- Donor: Литургический ритм + Heart Rate (для пиков)
- Order: Свидетельство Суда Почвы (для финальных ночей)
- Horizon: Карма-математика в моментах моральных весов
- Code: Сцена-функция (для контрактных сцен)
- Anthropos: Сенсорная инвентаризация (для межвидовых моментов)
- Eleyia: Синестезия (всегда)

Раздел описывает: принцип, формы реализации (2-3 варианта чтобы не было формулой),
правила применения, где НЕ применять, образец полного применения.]

## Шаблоны по типу поста
[Скелеты VERDICT, STORY+POLL, PERSONA, CLIFFHANGER, специфичные форматы проекта]

## Образцы (3-5 эталонных постов)
[ссылки на лучшие посты проекта]

## Визуальный голос
[Палитра промптов, кадрирование, запреты для изображений]

## Чек-лист перед коммитом
[Бинарные проверки ✅/❌, включая Sub Rosa-эквивалент для STORY]
```

### Текущие проекты

- **Vienna Special:** требует написания (доделать после финала)
- **Kingmaker:** требует написания (до старта Phase 1)
- **Orchid, Donor, остальные:** до старта своих сезонов

## 5. МЕХАНИКИ (per project)

### Reputation Mining (KM)
Каждый претендент имеет котировку. Опросы и Black Velvet сливы двигают её. Котировки видны в STATS POST раз в фазу минимум.

### Affinity / True Route (универсально, активируется в KM первым)

Пороги:
- **25%** → Скрытая привычка (DOSSIER)
- **50%** → Flashback (NOTEBOOK PAGE)
- **75%** → Shadow Preferences (короткая STORY)
- **100%** → Теневой Хук (главный секрет персонажа)

Финал имеет несколько концовок, доступных по комбинации аффинити.

### Black Velvet / Channel Six / эквивалент
Канал утечек - инструмент протагониста. Слив имеет цель, тональность, последствие на котировки.

### Stats хранение
`02_SYSTEM/STATE.md` или отдельный `STATS.json` - источник чисел. Не выдумываются на лету.

## 6. ПРОМПТЫ ДЛЯ ИЗОБРАЖЕНИЙ (REVE.AI)

Платформа: **app.reve.com**. Не Midjourney. Без флагов `--ar --v --style --s`.

### Формула
```
[CHARACTER TAG с ИМЕНЕМ] + [scene + environment + lighting] + [quality tags] + [aspect ratio]. No text, no logos.
```

### Имя персонажа - ВСЕГДА
Не «young woman» - писать «Theodora, late twenties Serbian woman». Не «professional woman» - «Alex Weiss, 32-year-old». Это для консистентности образа на разных постах.

### Базовые quality tags (всегда)
`Photorealistic, 8k, cinematic style, high contrast shadows, vibrant rich colors, cinematic color grading, high-end fashion editorial photography, shot on Kodak Portra 800, model-like features, editorial model appearance, perfect symmetrical face`

### Per-project палитра
- **Kingmaker:** `Quiet Luxury Noir, dark interior, candlelight, obsidian and gold palette`
- **Vienna Special:** `backstage atmosphere, cold halogen lighting, documentary photography style`
- Остальные - задать в `VOICE_LOCK.md` проекта при старте сезона.

### Aspect ratio
Текстом: `Square frame 1:1` / `Vertical frame 9:16` / `Horizontal frame 16:9`.

### Брендинг
В Novells - **без брендинга** (никаких подписей, логотипов, имени канала на изображении). Финал: `No text, no logos`.

См. [[feedback_novells_prompts]], [[feedback_novells_prompts_reve]].

## 9. ЗАПРЕТЫ (ЖЁСТКИЕ)

- Эм-тире (—) - только дефис (-). См. [[feedback_dashes_universal]].
- Брендинг в Novells (нет логотипов, нет имени канала на изображениях).
- Midjourney-флаги в промптах (нет `--ar`, `--v`, `--style`, `--s`).
- Сюжетные посты без прошедшего опроса о персонаже/конфликте.
- Реальные даты в нарративных файлах и постах (только в POSTING_SCHEDULE.md).
- Кроссоверы между проектами (изолированные миры).
- Перезапись или удаление утверждённых концовок без согласия пользователя.

## 10. РАБОЧИЙ ЦИКЛ ДНЯ

```
1. АУДИТ - запустить `tools/audit.sh <project>` (см. [[feedback_novells_audit_before_writing]])
   - Скрипт выводит: публикации за 7 дней / STATE / последние опросы /
     STATS (если есть) / временную шкалу / напоминания
   - Дополнительно проверить ручно:
     - Какие персонажи опрошены, какие нет?
     - Что напрашивается на сегодня?

2. ПЛАН ДНЯ
   - Предложить пользователю структуру дня
   - Подтвердить нарративный темп (особенно в эластических фазах)
   - Получить «да» перед написанием

3. СИСТЕМА
   - Обновить POLL_LOG с результатами вчера
   - Обновить STATE / STATS с движением чисел
   - (Sonnet 4.6)

4. НАРРАТИВ
   - Написать VERDICT
   - Написать STORY+POLL слоты
   - Написать CLIFFHANGER / STATS
   - (Opus 4.7)

5. ПРОВЕРКА
   - Эм-тире = 0
   - Имена персонажей в промптах
   - Опросы валидны (2-3 опции, значимо разные)

6. КОММИТ
   - git commit с описательным сообщением
   - Не пушим без явной просьбы пользователя
```
